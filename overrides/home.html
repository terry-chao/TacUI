开源 · MIT · Windows + D3D12

TacUI

声明式重建，直写零重建。

一个 GPU 加速、retained mode 的界面库：C++ 核心用 三棵树（VNode / Element / RenderObject）承接声明与 diff， 再用 base / override 双通道把高频动画从重建里摘出去； 跨语言只走一层稳定的 C ABI，宿主语言用它自己的原生语法写 UI —— 没有 XML，没有独立脚本。

功能

把「声明」和「高频变化」拆成两条路

这是整个设计的支点。声明式重建适合描述 UI，却不适配每帧都在变的动画与外部数据； 所以每个可动画属性都有两个通道，优先级只有一条规则。

两条变更通道

路径 A 改 state → 重建 VNode → diff → 写 base；路径 B 直接写 override → 只重绘。 生效值是 override ?: base，没有第二套优先级。

两条变更通道

三棵树 + diff

不可变描述 + diff + 稳定身份（Flutter 式骨架），不是可变对象原地改的 WPF 模型。 无反射、可热重载、可测试，跨语言传递同一份语义。

架构说明

C ABI 唯一边界

内部 struct 永不暴露，宿主只拿 NodeRef。代际句柄挡住悬垂引用， 一次 FFI 提交整棵子树，为 v1→v2（SoA buffer、渲染线程）留出 drop-in 的空间。

C ABI 与绑定

Retained GPU 渲染

保留视觉树 + 保留 GPU 资源：属性变化只更新 uniform / transform，不重建 GPU 对象。 每元素持有自己的 GPU 资源，生成一次就复用。

渲染架构

解析式反锯齿

AA 走解析覆盖而不是超采样：矩形、圆角、文字各有自己的解析路径。 这不是可选项 —— 节点图连线是贝塞尔曲线，AA 必须进 M1。

方案 §3.3

原生声明式 DSL

不同语言用各自的惯用法表达同一棵树：Rust 的 proc-macro、C# 的 source-gen、 Python 的 context manager。core 提供 builder 基座，各语言只写薄薄一层。

对外 API

可嵌入的 core

core 不带宿主语言依赖，能嵌进已有进程：已经拥有窗口与渲染器的应用， 自己驱动 update() 与 paint() 即可，完全不碰 host。

写一个 UI

12 个基本控件

label / button / checkbox / radio / switch / slider / progress / divider / panel / list item / tabs / text input。组件是函数不是类， 状态由输入系统持有 —— 亮起来的区域和响应的区域不可能漂移。

工作流

一帧里，四条路各走各的

输入改变状态，状态触发重建；动画不碰树，直接写 override。决定权在单个属性上， 框架里没有「这是动画控件」这类特判。

  1. 1 · 声明

    宿主语言构建一棵不可变 VNode 描述，一次 FFI 提交整棵子树。

  2. 2 · diff

    按稳定身份对账：create / update / destroy，只把变化落到 Element 树的 base。

  3. 3 · 直写

    动画与外部数据写 override：不标脏、不重建，只重绘受影响的那一层。

  4. 4 · 绘制

    RenderObject 树产出 DrawBatch，交给解析 AA、Glyph Atlas 与 RHI。

  • 路径 A 改 state重建diffbase
  • 路径 B override
  • 生效值 override 若 token 活跃，否则 base

架构

六层，只有一个跨语言边界

L4 是唯一暴露给宿主语言的面；L0–L3 永远不直接跨出去。想深挖哪一层，直接点进去。

L5 DSL / 宿主语言层Rust · C# · Python · Swift · TS 各语言用原生语法表达 UI，产出紧凑的 VNode 构建调用序列。 L4 Binding 层capi/ · C ABI + IDL 唯一的稳定 ABI 边界：代际句柄、回调表、版本协商。 L3 Framework 层core/framework Element 树（diff + state）与 RenderObject 树（layout / paint）、控件库、输入路由。 L2 Scene / Retained 层DrawBatch · GPU 句柄 Layer 树、脏标记与属性快照：base 落在这一层，override 在这一层叠加。 L1 Renderercore/renderer 批处理、解析式 AA、Glyph Atlas、矢量路径与合成器。 L0 Platform / RHIrhi/ · platform/ · host/ D3D12（第一版）、窗口、输入；IME / DPI / 无障碍按里程碑补。

为什么声明够快

重建的边界是重建的代价。diff 只改动到的 base，布局与绘制只在 base 变化时触发，动画不进这条路。

为什么直写安全

override 只开放 paint-only 属性（translate / scale / rotate / opacity / color）。影响布局的属性必须走重建。

为什么能跨语言

内部 struct 从不跨越边界，宿主只拿 NodeRef。所以内部实现换成 SoA buffer 也不破坏绑定。

快速开始

三条命令，把 M0 基线跑起来

Windows、MSVC、CMake ≥ 3.25 与 Windows SDK。核心无第三方依赖，不需要 vcpkg。

PowerShell 
cmake -S . -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Debug

# 先跑这个：列表 + 选中 + 详情 + 动画指示条
.\build\bin\asset_browser.exe

# 控件总览（也是控件层的自测）
.\build\bin\controls_gallery.exe

# 验收 M0 六条标准
.\build\bin\m0.exe --selftest
