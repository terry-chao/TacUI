# 踩坑与注意事项

> 这份清单是**从真机上抓到的缺陷**，不是理论风险。每一条都写清
> **症状 → 根因 → 修法 → 可推广的规矩**，因为症状会换个地方再来一次。
>
> 大部分条目由**基建**（帧回读、`stats`、headless 断言）发现，而不是肉眼。
> 这正是 [方案](plan.md) §6.1 想说明的事：UI 库的正确性靠可观测性，不靠盯着看。

---

## 一、D3D12 / 渲染

### 根常量按位传递，类型错配是静默的

**症状**：几何整体退化、画面错位，但调试层一声不吭。

**根因**：把 `instanceBase` 以 `float` 传进声明为 `uint` 的根常量。根常量是原始
32 位值，`float` 的位模式被重新解释成整数 → 越界读 → 读到 0。

**修法**：CPU 侧结构体与 HLSL `cbuffer` 严格同构，并用 `static_assert(sizeof(...))`
对齐（`d3d12_sdf_batch.cpp` 的 `FrameConstants`）。

**规矩**：**校验层抓不到内存语义的错误。** 只有帧回读 + 像素断言能发现。所以
「能出图、能对像素做断言」是渲染层的基建，不是附加功能。

### `GetAlphaTextureBounds` 用空矩形代替报错

**症状**：字形全是空白，但不报任何错。

**根因**：纹理类型与渲染模式不匹配时，它返回**空 rect 而非失败**。实测 Segoe UI 上
所有 `ALIASED_1x1` 组合都返回空，只有 `CLEARTYPE_3x1` 出墨（与文档直觉相反）。

**修法**：把工作组合排第一，其余留作回退；空结果被当作「无墨」而不是错误。

**规矩**：**遇到返回 0/空的 API，先确认那是「没有」还是「失败」。** 两者混淆会
让你在错误的方向上优化。

### 交换链后缓冲初始状态是 COMMON

**症状**：调试层在第一次屏障报错。

**根因**：翻转模型的后缓冲初始状态是 `COMMON`，不是 `PRESENT`。

**修法**：用 `firstUse_[idx]` 标记，首次屏障的 `StateBefore` 写 `COMMON`。

### `ResizeBuffers` 前必须释放所有后缓冲引用

**症状**：`ResizeBuffers` 返回 `DXGI_ERROR_INVALID_CALL`。

**根因**：还持有 `ID3D12Resource` 引用（RTV 建立时拿的）。

**修法**：`releaseRenderTargets()` 先 `Reset()` 全部后缓冲，再 `ResizeBuffers`。

### 不设视口就什么都不画

**症状**：命令都提交了，屏幕全黑。

**根因**：没有 `RSSetViewports` 时不做任何光栅化。

**修法**：`beginFrame` 里显式设视口和 scissor。

### 裁剪没有走设备状态

**症状**：滚动内容溢出视口。

**背景**：一次 instanced draw 覆盖整帧，用 scissor 状态栈会强制切断 draw。

**修法**：clip 放进**每个实例**的数据，片元着色器里 `discard`（见
[渲染管线](rendering.md)）。代价是 20 字节/实例、被裁的边是硬边。

**规矩**：**批处理与状态栈常常互斥。** 选择批处理就要接受把状态下沉到图元。

## 二、文本

### `GetGlyphIndices` 要 UTF-32，不是 UTF-16

**症状**：整形结果全是 `.notdef`（豆腐块）。

**根因**：`wchar_t*` 直接 reinterpret 成 `UINT32*`，两个 UTF-16 代码单元被当成
一个码点。

**修法**：`utf16ToUtf32` 显式转换（含代理对）。

### UV 用了纹素中心内缩，文字系统性发软

**症状**：文字发糊，重采样痕迹明显，但看不出是哪一步。

**根因**：quad 跨 `w` 个像素、边界到边界，而 UV 是 `(x+0.5)/size … (x+w-0.5)/size`。
两者不匹配 → 把 `w` 个纹素塞进 `w` 个像素，**每个像素都在双线性混合邻居**。

**修法**：改成边界到边界 `x/size … (x+w)/size`，严格 1:1 贴图。实测文字密集
区域边沿能量提升约 **1.65x**，纯背景 0 像素变化。

**规矩**：**位图与屏幕像素对齐时，UV 要边界到边界。** 纹素中心内缩是给
「采样一个连续场」用的，不是给 1:1 贴图用的。

### 小数位置贴位图，被线性采样器重采样

**症状**：文字发糊（与上一条是**两个独立原因**）。

**根因**：字形 pen advance 是小数（排版正确），按小数位置画位图会被重采样。

**修法**：**吸附字形原点**到整物理像素，**保留小数 advance**。同一基线上字形
相对偏移恒为整数，所以字距不变、字形变清晰。

### 进程没有声明 DPI 感知

**症状**：150% 缩放的显示器上一切都被重采样，文字最明显。

**根因**：进程不感知 DPI，Windows 把整个窗口位图拉伸 1.5 倍。

**陷阱**：`GetDpiForSystem()` 从**非 DPI 感知**的进程里问会返回 96，
于是误判成 100%（真值要去 `HKCU\...\WindowMetrics\AppliedDPI` 读）。

**修法**：声明 Per-Monitor V2；窗口/后缓冲走物理分辨率，UI 保持逻辑单位，
字形按 `fontSize × scale` **在物理像素上光栅化**。

### 字体回退的 face 身份不能用指针

**症状**：加了字体回退后，字形缓存全失效，每次 rebuild 都重新光栅化。

**根因**：`MapCharacters` 返回的 `IDWriteFont*` 不保证跨调用稳定，按指针做键会
每次造一个新 face。

**修法**：稳定身份 = `家族名|weight|style|stretch`。

### 字形缓存键要带 face

**症状**：中文和英文的同号字形串味。

**根因**：glyph index 只在**字体内部**唯一。

**修法**：`GlyphKey = (face, glyphIndex, sizeBucket)`。

### 图集无条件重传

**症状**：每次 rebuild 都 1 MiB memcpy + 全纹理上传（32 次），且随 rebuild 增长。

**根因**：标脏无条件。

**修法**：只有 `rasterized` 计数真的变了才标脏。稳态零上传。

## 三、窗口与拖动

这一节是**同一件事的三次迭代**，值得整段读。

### 拖边框时画面被拉伸、抖动

**根因**：Windows 的模态 resize 循环（`WM_ENTERSIZEMOVE` 之后由 `DefWindowProc`
接管）会**同步**调 `WM_SIZE`，而 `host::run` 的帧循环卡在 `DispatchMessageW`
里出不来 —— 既不 `ResizeBuffers` 也不出帧，DWM 就把旧尺寸的画面拉伸铺到新窗口。

**弯路一（错的）**：`WM_SIZE` 只记尺寸 + 1ms 定时器合并处理。结果**拖得慢也抖** ——
探针实测步进后**立刻**采样，内容是按旧缓冲被拉伸的（按钮右边缘在 238），等定时器
跑完才跳回 233。**结论：缓冲区尺寸必须始终等于窗口尺寸，一帧都不能滞后。**

**弯路二**：把 GPU 工作搬到渲染线程（对）+ 尺寸握手（对），但渲染线程用
`condition_variable::wait_for(7ms)` 轮询尺寸 —— 被系统定时器粒度放大到 ~15.6ms，
整个应用被**静默压到 60Hz**（m0 的 frame/paint 断言抓住）。

**最终做法**（四件事缺一不可）：

1. **device 与所有 GPU 调用搬到渲染线程**；UI 线程只做消息泵 + `ui.update()`，
   `WM_SIZE` 里只剩两个原子写。每步 `WM_SIZE` 成本 **4.70ms → 1.63ms**。
2. **同步 resize**：`Win32Window::setResizeFn` 收到 `WM_SIZE` 就让渲染线程 resize
   交换链并重绘。
3. **拖动期间握手**：`setDragFn` 报告 `WM_ENTERSIZEMOVE/EXITSIZEMOVE`；拖动时等到
   渲染线程真正 resize + 呈现完成再返回。复测连续 10 步，**每一步之后立刻采样都一致**。
4. **合并排队中的 `WM_SIZE`**：快拖时队列会堆积，`PeekMessage` 一次抽干只取最新
   尺寸，一次工作跟到最新，不再追赶中间态。

### 拖动期间关 vsync，重绘走 `Ui::repaint()`

**根因**：vsync 每步等一次会让窗口落后指针，桌面持续拉伸「一帧前」的画面。

**修法**：`setVSync(!resizing && !dragging)`；重绘走 `Ui::repaint()` ——
**只重发上次收集好的 draw list，不重新遍历树**（内容本来就不随窗口尺寸变化）。
每步 `draw+present` 从 2.57ms 降到 **0.50ms**。剩下的 `ResizeBuffers`（1.73ms）
是硬下限（`waitForGpu` 只有 0.01ms）。

**规矩**：**帧循环的节拍只能来自 Present。** 任何定时等待都会落到系统定时器粒度上，
把帧率钉死在一个你没写过的数字上。

### `WM_MOUSEWHEEL` 用的是屏幕坐标

**症状**：滚轮位置错位。

**根因**：所有鼠标消息里，只有滚轮带的是**屏幕坐标**。

**修法**：`ScreenToClient` 转换后再上报。

## 四、C ABI 与绑定

### ctypes 不校验结构体大小 → 静默写穿缓冲区

**症状**：宿主侧内存被静默破坏，无任何报错。

**根因**：`ui::Stats` 加了字段，C 侧 `tui_stats` 没同步；`tui_get_stats` 径直写穿
宿主缓冲区。

**修法**：导出 `tui_stats_size()` / `tui_event_size()`，绑定在 **import 时**比对
`sizeof`，把静默破坏变成加载期报错。

**规矩**：**跨语言结构体必须有尺寸握手。** 没有它就等于赌两边永远同步。

### `wchar_t` 宽度不跨平台

**症状**：`tui_run` / `tui_capture_next_frame` 收 `const wchar_t*`，而 header 自己
写着「字符串一律 UTF-8」；`wchar_t` 在 Windows 是 2 字节、Linux 是 4 字节。

**修法**：统一 UTF-8。

**规矩**：**一个打算给多语言用的 ABI 里不能出现 `wchar_t`。**

### ctypes 回调里抛异常不会传播

**症状**：宿主回调里的错误静默丢失。

**根因**：异常穿过 C 循环没有定义行为，ctypes 直接吞掉。

**修法**：ABI 需要一条错误回传路径（M1）；在那之前，回调里自己 catch。

### 有状态控件的状态必须由库托管

**原因**：C++ 控件把「编辑缓冲/滚动偏移的引用」捕获进**行为**（会活过 build）。
如果宿主传一个缓冲区进来，那个引用会悬垂。

**修法**：库按控件 key 托管状态（`unordered_map` 保证元素引用在 rehash 时稳定），
宿主经 `tui_text_get/set`、`tui_scroll_offset` 等访问器读写。

### 首帧回调不能早于建树

**症状**：宿主在 frame 回调里解析句柄必然失败。

**修法**：`tui_run` 在第一次 frame 回调**之前**先 build 一次。

**规矩**：**只有写第二个宿主语言才会暴露这类时序问题。** 换语言不只是翻译 API。

## 五、控件与输入

### 同一个 key 只能注册一次行为

**症状**：滑块的拖动或方向键其中一个失效。

**根因**：`b.behavior(key, …)` 是「写」不是「追加」，第二次覆盖第一次。

**修法**：一张 `NodeBehavior` 同时带 `onDrag` 和 `onKey`。

### 命中盒必须**就是**视觉盒，不能是另一个数字

**症状**：改了视觉忘了改命中，点不到 / 点错。

**修法（三条约定，都在 `controls.cpp`）：**

- 控件把 key 放在**外层矩形**上（也就是视觉范围本身），命中盒和绘制盒是同一个对象；
- 视觉比行窄的控件（checkbox / slider / text field）额外放一个**透明的带 key 矩形**
  覆盖整行，于是点标签也生效；
- 焦点环、描边这类「更大的盒子」**不带 key**。

### 没有 stroke 图元，1px 描边是两个矩形

**取舍**：外描边色矩形 + 内缩 1px 填充矩形。圆角处与真正的描边不完全等价，已知。

### 滚轮到端点要 `return false`

否则嵌套滚动里手势死在最内层，外层再也滚不动。

### hover 必须在 rebuild 之后重算

指针没动、树动了，hover 就可能错。做法是在 `update()` 里、build **之前**重跑命中测试。

### 直写属性如果动了布局，整个快路径要返工

`OverrideToken` **不提供**任何布局相关 setter。这条边界靠 API 形状守住，
不靠文档提醒。

## 六、测试与基建（元教训）

上面几乎每一条都是**基建**发现的，不是肉眼发现的。所以这些基建本身值得当成产品的一部分：

| 基建 | 抓住了什么 |
|------|------------|
| 帧回读 → PNG | 根常量位模式错误（校验层完全静默） |
| `stats` 计数 | 图集每次重传、`liveOverrides` 停在旧值 |
| `m0 --selftest` 的 frame/paint 断言 | 帧循环被静默压到 60Hz |
| headless 输入注入（无窗口无 GPU） | 交互语义回归，可进 CI |
| 记录型 `rhi::Device` | 绘制顺序交错、scissor 有无意外 |
| `textprobe`（无 GPU） | 字体回退、UV 跨度、`.notdef` |
| 尺寸握手探针 | resize 抖动（肉眼说不清，探针能给出数字） |

**三条可推广的规矩：**

1. **能出图、能对像素/计数做断言，比「看起来对」可靠一个数量级。**
2. **每帧都要准的统计，必须放在每帧都跑的函数里**（`liveOverrides` 的教训）。
3. **跨语言、跨线程、跨 DPI 的问题，往往只有换一个宿主 / 换一台设备才暴露。**
   尽早引入第二个宿主语言和第二台显示器配置，成本远低于事后返工。
